# Превью React-компонентов

Расширение добавляет к `.jsx` и `.tsx`-файлам CodeLens `Preview: <название>`. Нажатие на него открывает React-компонент в соседней панели VS Code.

## Требования

- VS Code 1.85 или новее;
- доверенный workspace VS Code;
- React-проект с установленными `react` и `react-dom`;
- React 18 или новее, потому что рендер выполняется через `react-dom/client`;
- экспортируемый компонент: named export или default export.

Расширение использует `esbuild` для сборки компонента и его импортов. Стили CSS подключаются автоматически, а изображения и шрифты основных форматов встраиваются как data URL.

## Запуск и установка

Для разработки этого workspace откройте проект в VS Code и нажмите `F5`. Запустится отдельное Extension Development Host окно с текущей версией расширения.

Чтобы собрать VSIX локально:

```bash
npx --yes @vscode/vsce package --allow-missing-repository
```

Затем установите созданный `.vsix` через команду VS Code `Extensions: Install from VSIX...`.

## Синтаксис

Каноническая форма — короткая однострочная директива в комментарии. Исходный файл остаётся валидным JSX/TSX и продолжает работать в обычном приложении:

```tsx
// #preview Button {"label":"Continue"}
```

Полная форма:

```text
// #preview "Название превью" ИмяЭкспорта {JSON props}
```

Правила:

- `#preview` — обязательное начало;
- название в кавычках необязательно; если его нет, используется имя экспорта;
- `ИмяЭкспорта` — имя named export или `default` для default export;
- props — необязательный JSON-объект; если его нет, передаётся `{}`;
- блочный `/* #preview ... */` также поддерживается для совместимости.

Если JSON props недостаточно, можно передать JSX-body. Это позволяет использовать вложенные компоненты, функции и локальные импорты исходного файла:

```tsx
// #preview("Card with content") { <Card><Button>Continue</Button></Card> }
```

Тело добавляется к исходному файлу только во время preview-сборки и не меняет файл на диске. Для многострочного JSX можно использовать блочный комментарий:

```tsx
/* #preview("Dialog") {
  <Dialog open>
    <Button>Close</Button>
  </Dialog>
} */
```

Примеры:

```tsx
export function Card({ title, tone = "neutral" }) {
  return <article data-tone={tone}>{title}</article>;
}

// #preview "Neutral card" Card {"title":"Hello"}
// #preview "Warning card" Card {"title":"Attention","tone":"warning"}
```

Для default export:

```tsx
export default function EmptyState({ title }) {
  return <p>{title}</p>;
}

// #preview "Empty" default {"title":"Nothing here"}
```

## Комплексный preview-модуль

Если нужна одна демонстрационная страница с несколькими состояниями и компонентами, используйте блок `#preview-module`:

```tsx
/* #preview-module("Component gallery")
const demos = [
  <Button label="Primary" />,
  <Button label="Disabled" disabled />,
  <ErrorMessage text="Something went wrong" />,
];

return <div className="grid gap-4">{demos}</div>;
*/
```

Содержимое блока является телом отдельного preview-компонента. В нём можно объявлять переменные, локальные функции и возвращать любой JSX. Блок добавляется только во время preview-сборки и не попадает в обычную сборку приложения. Не добавляйте в него `export` или `import`: импорты и компоненты из исходного файла уже доступны внутри блока.

## Несколько превью

В одном файле можно объявить любое количество директив. Каждая появится отдельным CodeLens, а открытие нового CodeLens заменит содержимое уже открытой панели.

## Обновление

При сохранении исходного файла открытое превью пересобирается автоматически. Поведение можно отключить настройкой `reactPreview.refreshOnSave`.

В панели preview есть кнопка `Reload`, а ту же операцию можно вызвать командой `React Preview: Reload Current Preview`.

Несохранённый файл также можно открыть вручную: расширение передаёт текущий текст документа в сборщик. При сохранении список CodeLens и выбранные props перечитываются из файла.

## Ошибки

Некорректная директива подсвечивается диагностикой прямо в редакторе. Если экспорт не найден, JSX/props некорректны или зависимость не разрешается, в панели появится ошибка сборки. Проверьте:

- что `react` и `react-dom` установлены именно в React-проекте;
- что имя в директиве совпадает с экспортом;
- что props являются валидным JSON, например `{"size":"large"}`;
- что импорт компонента доступен из текущего workspace.

## Ограничения текущей версии

- в короткой форме props задаются JSON-объектом; для функций, JSX и сложных runtime-значений используйте JSX-body;
- preview-файл должен находиться в workspace с доступными зависимостями;
- для React 17 и старше потребуется заменить рендерер на `react-dom.render`;
- сложные alias-настройки и нестандартные asset loaders зависят от того, насколько их может разрешить `esbuild` без конфигурации основного bundler-а.
